# C3 model 17100007 native LAN support

Model `17100007` uses the vendor's table protocol rather than the legacy C3
`0x01` basic query/control. The source is
`T_0000_C3_10004830_2025112601.lua`, vendor Lua version 0.0.27, from the
SmartHome device plugin cache. The filename identifies product 10004830;
the connected controller identifies itself as model 17100007.

## Queries and controls

The `0x00` message body has a ten-byte envelope: body type, two-byte table,
four reserved bytes, format byte, and two reserved bytes. Format 0 is a
sequential table; format 1 contains two-byte tags, one-byte lengths and values.
The basic query body is `002010ffffffff00ffff`.

Each refresh requests basic state (`0x2010`), overall/DHW energy (`0x2F12`),
heating/cooling energy (`0x2F11`), operating telemetry (`0x2F10`), and running
flags (`0x2F17`). One of silent (`0x2050`), ECO (`0x2070`) or disinfection
(`0x2090`) is requested per refresh in rotation: six requests in total.
Each table has an independent request class for unsupported-query tracking.

Existing APIs support zone power, mode, zone/room targets, DHW power/target,
weather-curve enable, fast DHW, tank booster, silent mode/level, ECO enable
and scheduled-disinfection enable. A silent-level selection sends its level
and enable flag atomically. Disinfection enable does not request an immediate
disinfection cycle. Calendar/timer editing and installer settings are excluded.

Writes are sparse TLVs containing only the requested changes, never cached
default settings for other zones. Temperature targets use signed tenths;
half-degree changes are preserved. Writes require an initial basic response,
check the reported temperature limits, and reject controls for an unconfigured
second zone. Unknown controls cannot fall back to legacy packets on this model.
Sparse replies preserve fields they do not contain; invalid sentinels become
`None`. Malformed TLVs do not partially update state.

## Curated telemetry

Existing temperatures, compressor/fan data, circulation/valve flags and basic
capabilities remain available. Energy tables add 57 named metrics:

| Scope                 | Metrics                                                         |
| --------------------- | --------------------------------------------------------------- |
| Overall               | Heat output, instantaneous COP, cumulative COP                  |
| Heating, cooling, DHW | Electrical power, thermal output, instantaneous COP             |
| Heating, cooling, DHW | Cumulative electricity, thermal energy and COP                  |
| Heating, cooling, DHW | Today, week, month and year electricity, thermal energy and COP |

New powers are kW, energies kWh, and COP/EER dimensionless. The existing
`instant_power0` and `instant_renew_power0` remain W. The existing
`total_energy_consumption` and `total_produced_energy` become scaled kWh
from `0x2F12` on this model; older unscaled telemetry cannot overwrite them.
`dhw_power` remains a boolean: electrical kW uses `dhw_power_consumption`.

Values come from the controller, including its period COP and energy counters.
Their averaging, reset boundaries and accounting for standby/circulation or
auxiliary loads have not been independently established. A reported zero power
does not prove zero grid consumption. Use an external meter for whole-appliance
consumption or billing. Do not average instantaneous COP to obtain period COP.
Unavailable values stay unknown rather than becoming zero.

No generated raw-field registry, serial-number tables, repeated schedule slots,
installer editors or per-installation exclusions are added. Other C3 models
retain their existing protocol. New energy attributes exist only on 17100007.

## Validation and limits

A real controller answered the basic LAN query and the read-only table probes.
A DHW-only 49 degree Celsius write was confirmed on hardware. Other writes
are validated against literal vendor-encoded packets, not hardware acceptance.
Sanitized response fixtures retain protocol layouts with synthetic counters;
expected values were independently decoded using the vendor Lua.

The C3 suite covers sequential and sparse replies, truncation, invalid values,
units, query rotation, control isolation and legacy behavior. It achieves 100%
statement and branch coverage locally. Hardware verification across other
installations and upstream CI/Codecov review are still required.

The companion Home Assistant mappings are optional sensors. They need a library
release containing this support; maintainers update the integration dependency
pin centrally. This contribution does not change a release version.
