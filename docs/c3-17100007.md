# C3 Model 17100007 Telemetry

This read-only decoder is based on the idle/running raw frames and synchronized
wired-controller readings in
[PR #211, comment 6175798884](https://github.com/wuwentao/midea-lan/pull/211#issuecomment-6175798884).
The available `17100003` and `171000AU` Lua files are not this model's protocol.
The new `20B0` and `2F10` layouts are therefore restricted to model `17100007`.

## Decoded Values

Offsets are zero-based within the X00 body, including the leading `00`. Integer
fields are big-endian. Temperatures use sign-magnitude U16 tenths of a degree
Celsius, with `ffff` representing an unavailable sensor.

The existing `2010` basic-state decoder also publishes `idu_t1s1` from offset 14
for this model only. Its existing target, tank, and outdoor fields remain
available without a model argument.

The minimum temperature bodies remain 26 bytes (`20B0`) and 23 bytes (`2F10`).
Each later field is decoded only when all its bytes are present. Missing tails
leave previous device values unchanged rather than overwriting them with zero.

## Compatibility And HA Entities

Legacy X10/X05 `water_flower` and `current_unit_capacity` retain their existing
raw-U16 API. Their values must not be assumed to use the normalized units of the
model-specific X00 decoder. A future uniform-unit API needs a coordinated library
and HA migration, not a silent rescaling of existing devices.

`pump_i_pwm` is sourced from push messages. Some legacy X10 firmware does not
populate its query PWM byte, so that byte only updates the legacy
`pwm_pump_out` response field and cannot erase a valid `pump_i_pwm` reading.

The four new attributes (`comp_run_time`, `fan_total_run_time`,
`pump_i_total_run_time`, `pump_i_pwm`) are library state, not automatically new HA
entities. Companion `midea_ac_lan` mappings and translations need minutes, hours,
hours, and percent respectively. HA's existing raw-capacity label also needs a
model-aware update before describing X00 capacity as a kW entity.

## Next Validation

- Capture synchronized, steady-running controller readings to verify the
  provisional capacity and DC-current scales; each currently has just one
  nonzero sample.
- If a normal operating cycle exceeds 255 minutes, capture the session-runtime
  rollover to establish whether byte 118 is its high byte. Do not change normal
  device operation solely for this test.
- Keep `20B1`, `2F11`, `2F12`, byte 147, operation mode/status, frequency-limit
  type, IDU target frequency, and IBH runtimes undecoded until model-specific
  protocol or changing controller-correlated samples establish their meanings.
- Query initialization and shared request/reply matching remain separate work.
  Unsolicited pushes are not proof that the legacy queries are supported.
  Obtain the matching Lua or a known-valid query/reply exchange before adding
  model-specific polling; validate reconnect/availability independently.
